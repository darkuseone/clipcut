# ClipCut — нарезка стримов для Content Rewards

Главная инструкция проекта. Claude читает её в начале каждой сессии.
Общаемся по-русски. Пользователь работает с телефона, компьютера нет: всё качается, режется и рендерится в облачном контейнере.

## Роли
- **Пользователь:** выбирает кампанию на Content Rewards (contentrewards.com / Whop) и вступает в неё, кидает ссылку на кампанию и/или на стримы, говорит, сколько клипов нужно. Сам выкладывает клипы в TikTok / Shorts / Reels и сам отправляет ссылки в кампанию.
- **Claude:** читает условия кампании, скачивает стрим в контейнер, режет клипы по правилам, проверяет их, отдаёт файлы и текст для выкладки. Ничего не публикует и не отправляет сам.

## Правила (читать перед каждой нарезкой)
Порядок приоритета, если правила противоречат друг другу:
1. **ТЗ конкретной кампании.** Файл `campaigns/<кампания>.md`, его составляем со страницы кампании. Оно главнее всего: формат, длина, обязательный текст и теги, запреты, площадки.
2. `docs/rules/01-clip-rules.md` — какие моменты брать, длина, начало, конец, оценка.
3. `docs/rules/02-clip-style.md` — как выглядит клип: 1080x1920, вебка сверху, слова субтитров по одному, хук, ник, звук.
4. `docs/rules/03-editing-workflow.md` — порядок работы. Облачные поправки ниже.
5. `docs/rules/05-checklist-12.md` — чек-лист на 12 правил.
6. `docs/rules/00-money-rules.txt` — общие правила заработка. `docs/rules/04-prompts.md` — исходные промты автора, используем как образец.

Справка по площадке — в `docs/content-rewards.md`.

## Текущие договорённости
- Только **американские / англоязычные стримеры**. Субтитры, хук и подписи на английском. В отчёте даём короткий перевод каждого момента на русский.
- Кампании выбирает пользователь. Claude может их искать, только когда попросят.
- Сколько клипов делать, говорит пользователь (например, «нарежь 5»). Если число не названо — 5.
- Режем только стримеров с разрешением: кампания, конкурс нарезок или прямое разрешение.

## Облачный процесс (вместо локальных папок из 03-editing-workflow)
Рабочая папка для видео — `work/`. Она в `.gitignore`: видео в git **не коммитим**, GitHub не принимает файлы больше 100 МБ.

```
work/<streamer>/<stream_id>/
  source.mp4              # исходник (yt-dlp)
  audio16k.wav            # моно 16 кГц для расшифровки
  transcript.json         # слова с таймкодами (faster-whisper)
  loudness.csv            # громкость каждые 0.5 с
  candidates.md           # 25–30 кандидатов с оценками
  clips/clip_01.mp4 …     # готовые клипы
  clips/checks/           # контрольные кадры 0/1/2 с и середина
  clips/captions.md       # текст для выкладки
```

Шаги:
1. **Кампания.** Если дали ссылку, читаем страницу и заполняем `campaigns/<slug>.md` по шаблону `campaigns/_template.md`: стример, ставка, бюджет, минимум и максимум, площадки, обязательный текст и теги, запреты, источники стримов. Коммитим.
2. **Скачивание.** `yt-dlp` в `work/...`. Если стрим длиннее ~3 ч, сначала качаем только нужный отрезок (`--download-sections`). Качество 1080p, если есть, иначе лучшее.
3. **Анализ.** Длина, разрешение, есть ли вебка и где она в кадре (YuNet по нескольким кадрам). Расшифровка: faster-whisper с таймкодами слов. Громкость каждые 0.5 с.
4. **Отбор.** Пики громкости сводим с текстом, собираем 25–30 кандидатов, оцениваем по 4 критериям из `01-clip-rules.md` и берём N лучших со средней оценкой ≥ 7 без пересечений. Список кандидатов **не ждёт подтверждения**: режем сразу и показываем его в отчёте.
5. **Рендер.** Раскладка, субтитры (ASS, libass), хук, ник, громкость −14 LUFS по `02-clip-style.md`. Шрифты лежат в `assets/fonts/`.
6. **Самопроверка.** Кадры с 0, 1, 2 секунды и из середины: первая секунда на пике, субтитры не на лице, лицо и действие в кадре, нет чёрных кадров, звук не обрезан. Кадры смотрим сами. Если что-то не так — переделываем клип и записываем, что исправили.
7. **Выдача.**
   - Каждый клип отправляем пользователю в чат через `SendUserFile`. Это основной способ, клип 20–45 с весит примерно 10–40 МБ.
   - Если файл не уходит или пользователь попросил ссылку, коммитим клипы в отдельную ветку `clips/<streamer>-<date>` и даём ссылку на скачивание с GitHub (raw). Каждый файл должен быть меньше 100 МБ. В рабочую ветку клипы не коммитим.
   - Текст для выкладки: один общий `captions.md` и коротко в чате после каждого клипа.
8. **Отчёт.** Таблица: №, файл, время в стриме, длина, оценка, хук, перевод момента на русский, что исправили. Плюс сколько всего заняло времени.

## Текст для выкладки (на каждый клип)
- Строка 1: хук до 8 слов, на английском.
- Ник стримера (@...), 3–5 хэштегов: стример + игра + то, что требует кампания.
- Обязательный текст и теги из `campaigns/<slug>.md`. Если в ТЗ их нет, ставим строку `[текст кампании]`.
- Если кампания — реклама бренда, напоминаем пользователю поставить отметку «платное партнёрство».

## Правки
На правку вида «клип 3 начни позже», «клип 7 замени» переделываем **только эти клипы**, остальные не трогаем. Отдаём заново только изменённые.

## Запреты
- Чужая музыка поверх клипа, моменты с громким игровым радио или песней.
- Личные данные, оскорбления по национальности, полу и подобное.
- Накрутка, казино, спам одинаковыми роликами.
- Пустой первый кадр, заставки, концовки.

## Окружение
- Установка: `bash setup.sh`. Ставит yt-dlp, faster-whisper, opencv, pyloudnorm, скачивает модель лица YuNet. ffmpeg (с libass и loudnorm) уже есть в образе.
- yt-dlp для YouTube нужен JS-рантайм: передаём `--js-runtimes node`, node уже есть в образе.
- GitHub raw и github.com/…/raw из контейнера заблокированы, кроме этого репо. Файлы с GitHub качаем через `cdn.jsdelivr.net/gh/...`, модели — с huggingface.co.
- Контейнер временный: исходники и клипы пропадают после сессии. Пользователь забирает клипы сразу.
